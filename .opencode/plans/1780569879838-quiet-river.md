## 3. Test Database Strategy

Use a **separate PostgreSQL database** (`messenger_test`). Configure via `.env.test` or env vars with a fallback:

### conftest_db.py — DB Engine & Session Fixtures

- **`test_engine` fixture** (session scope): creates an async engine pointing to a test DB (reads `TEST_POSTGRES_DSN` from env, falls back to `POSTGRES_DSN` with `_test` suffix).
- **`create_tables` fixture** (session scope, autouse): runs `Base.metadata.create_all` on the test engine once.
- **`drop_tables` fixture** (session scope, autouse, yield-fixture teardown): drops all tables after all tests.
- **`db_session` fixture** (function scope): begins a transaction, yields an `AsyncSession`, rolls back on teardown. This gives full isolation per test.

```python
# conftest.py pattern for per-test transaction rollback
@pytest_asyncio.fixture
async def db_session(test_engine):
    async with test_engine.connect() as conn:
        await conn.begin()
        session = AsyncSession(bind=conn, expire_on_commit=False)
        yield session
        await session.close()
        await conn.rollback()
```

## 8. Edge Cases to Cover Across All Layers

- **Empty states**: no users, no chats, no messages, no participants
- **Not found**: 404 for non-existent entities (user, chat, message, participant)
- **Duplicates**: 409 for duplicate username, duplicate participant
- **Unauthorized**: 401 for invalid/missing JWT
- **Boundary values**: message limit = 0, limit = large number
- **Transaction isolation**: each test runs in its own transaction that rolls back
