# Telegram-like React frontend for FastAPI messenger

## Context

The repo at `/home/nikitooosss/Code/messenger` currently contains only a FastAPI backend (`src/backend/`) with REST endpoints for users/chats/messages/participants and a WebSocket at `/ws` for real-time events. We are building a new Telegram-style SPA under a fresh `frontend/` directory that talks to this backend.

**Stack (decided with the user):** Vite + React 18 + TS, TanStack Router (code-based), TanStack Query, Tailwind, native WebSocket wrapped in a React context. Vite dev-proxy forwards all REST paths and `/ws` to FastAPI on :8000 so the HttpOnly `access_token` cookie is same-origin and works without CORS.

**Features in scope:** auth (login/register), chat-list sidebar with create-chat dialog, message view with real-time updates, online/offline presence, typing indicators, add/remove participants, edit/delete messages.

## Backend surface the UI binds to

REST (cookie-authenticated):
- `POST /auth/register` `{uniq_name, name?, password_hash(plain)}` → User
- `POST /auth/login` form `username=<uniq_name>&password=<plain>` → sets `access_token` HttpOnly cookie
- `GET /user/me` → User (the only auth-protected REST endpoint)
- `GET /user/get`, `GET /user/get/{id}` → list / single User
- `GET /chat/get?user_id=`, `GET /chat/get/{id}` → list / Chat
- `POST /chat/create` `{name, is_group}` → Chat
- `GET /message/get?chat_id=&limit=` → list[Message] (no ordering — sort client-side by `created_at`)
- `POST /message/create`, `PATCH /message/{id}`, `DELETE /message/{id}`
- `GET /chat_participant/get?chat_id=`, `POST /chat_participant/create`, `DELETE /chat_participant/{id}`

WebSocket `ws://<host>/ws` (cookie-auth). Discriminated-union JSON events, literal `type` field. Full client→server and server→client schemas in `src/backend/ws/schemas/registry.py:30`. We mirror them in TS.

> Gotcha: `POST /message/create` declares `response_model=MessagePost` which omits `id`/`created_at`. **Do not trust its body for cache writes** — always rely on the `message_created` WS event for the canonical record. Same caveat for chat/participant creation.

## Key implementation notes

### `vite.config.ts`
Proxy every backend path (and `/ws` with `ws: true`) to `http://localhost:8000`. This makes the SPA and backend share the `localhost` origin so the HttpOnly cookie flows on both REST and the WS handshake.

### `types/wsEvents.ts`
Mirror `backend/ws/schemas/registry.py:30` exactly. The literal `type` strings must match `TypeEvent` enum values in `backend/ws/schemas/events.py:27`. Two discriminated unions: `ClientEvent` (C→S) and `ServerEvent` (S→C).

### `apiClient.ts`
Single `request<T>(path, init)` helper. Always `credentials: 'include'`. Throws `ApiError(status, body)` on non-2xx. One method per endpoint. Use `URLSearchParams` + `Content-Type: application/x-www-form-urlencoded` for `/auth/login`.

### `WebSocketProvider.tsx`
- Build URL from `location.host` so dev/prod both work.
- Lifecycle: `onopen` flushes a queue of events sent while disconnected; `onclose` schedules reconnect with **exponential backoff + jitter** (`min(30s, 500 * 2^n) + random()*250`).
- Mount only when authenticated (`enabled` prop) — connecting before login causes a 401 close + infinite reconnect loop.
- Each `onmessage` calls `handleWsEvent(ev, queryClient)`.

### `handleWsEvent.ts` — single cache-mutator
For every `ServerEvent` type, mutate the relevant TanStack Query cache:
- `message_created` → append to `qk.messages(chat_id)` (replacing any optimistic temp with negative id matching content+user)
- `message_updated` / `message_deleted` → update/filter that list
- `message_deleted` → walk `getQueriesData({ queryKey: qk.messagesRoot })` because we don't know `chat_id`
- `chat_created` / `chat_updated` / `chat_deleted` → update `qk.chats()` and `qk.chat(id)`; on delete, also `removeQueries` for messages+participants
- `chat_participant_*` → update `qk.participants(chat_id)`
- `user_online` / `user_offline` / `user_start_typing` / `user_stop_typing` → forward to `presenceBus` (ephemeral state, **not** the cache)

### Optimistic send (`useSendMessage`)
- `mutationFn` returns a `Message` with `id: -Date.now()` and pushes it into `qk.messages(chatId)`.
- Send `{type:'message_create', message:{chat_id, user_id, content}}` over WS.
- The eventual `message_created` event replaces the temp entry.
- On `onopen` reconnect, `invalidateQueries({queryKey: qk.messages(currentChatId)})` to reconcile any missed messages.

### Typing debounce (`MessageInput`)
- On first keystroke: emit `user_start_typing`. Reset a 3s timer; on expiry emit `user_stop_typing`.
- On empty input, send, unmount, or chat switch: always emit `user_stop_typing` (cleanup effect).

### Presence (`presenceStore.ts`)
- Tiny `Bus` class with `emit/on`. `useOnline(userId)` subscribes and keeps a `Set<number>` of online ids; seeded from `is_active` on cached users. `TypingIndicator` subscribes filtered by `chat_id` and auto-clears any typer not refreshed in 5s (safety net for dropped `user_stop_typing`).

### Routing (`router.ts`)
Code-based tree:
```
rootRoute
├── /login      (LoginPage)
├── /register   (RegisterPage)
└── app         (pathless layout, beforeLoad: ensureAuthenticated, mounts <WebSocketProvider enabled/>)
    ├── /                            (EmptyChatPlaceholder)
    └── /chat/$chatId                (MessageView, parseParams: Number)
```

`ensureAuthenticated()` calls `qc.fetchQuery({queryKey: qk.me, queryFn: api.me, retry:false})` and throws `redirect({to:'/login'})` on 401.

## Verification — end-to-end smoke test

```bash
# Backend
uv sync
alembic upgrade head
uvicorn backend.api.main:app --reload --port 8000 --app-dir src

# Seed users
curl -X POST localhost:8000/auth/register -H 'Content-Type: application/json' \
  -d '{"uniq_name":"alice","name":"Alice","password_hash":"pw"}'
curl -X POST localhost:8000/auth/register -H 'Content-Type: application/json' \
  -d '{"uniq_name":"bob","name":"Bob","password_hash":"pw"}'

# Frontend
cd frontend && npm install && npm run dev    # http://localhost:5173
```

Manual checks:
1. **Auth redirect** — `/` while logged out → `/login`. Log in as `alice`/`pw` → lands on `/`. DevTools shows `access_token` HttpOnly cookie on `localhost:5173`.
2. **Sidebar** — Create a chat with Bob from the "New chat" dialog; chat appears in Alice's sidebar. Open Incognito, log in as Bob → chat appears via `chat_created` WS event with no refresh.
3. **Messaging** — Alice types → Bob sees "Alice is typing…" within ~100ms. Alice hits send → bubble appears immediately (optimistic, negative id) in her window, replaced by the canonical record when `message_created` arrives. Bob receives the message in real time.
4. **Edit/delete** — Edit/delete own messages via the bubble menu → `message_updated` / `message_deleted` propagate to both windows.
5. **Presence** — Close Bob's tab; Alice's sidebar shows his online dot disappear (`user_offline`). Reopen → `user_online` restores it.
6. **Participants** — Add a third user to a group chat → both members' participant lists update via `chat_participant_created`; the new user receives `chat_created` + `chat_participant_created` and sees the chat in their sidebar.
7. **Reconnect** — Stop uvicorn for ~10s; sending still works (queue). Restart → `WebSocketProvider` reconnects with backoff, queued events flush, and `invalidateQueries` refetches any missed messages.
8. **Build** — `npm run build` (runs `tsc -b && vite build`) passes with zero TS errors.
